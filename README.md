# GameEdge

面向游戏房间服务的 C++20 TCP 长连接网关实验项目。当前是**第一阶段**：单进程、单事件循环、单上游房间服务。它用于练习非阻塞网络 I/O、连接生命周期与背压；尚未完成性能调优，也未声称达到生产级低延迟。

## 架构

```text
玩家客户端 ── TCP 帧 ──> GameEdge ── TCP 帧 ──> 模拟房间服务
                       │
                       ├─ epoll（Linux）/ WSAPoll（Windows 开发测试）
                       ├─ 流式分帧与心跳
                       ├─ 每方向写缓冲区上限 1 MiB
                       └─ 空闲超时与优雅退出
```

网关只解释帧类型，数据帧负载保持不透明。客户端 Ping 在网关得到 Pong，不转发到房间服务。每条客户端连接对应一条上游连接；上游出错只关闭该会话。每次可读事件最多执行 16 次 8 KiB 读取，避免繁忙连接独占事件循环。上游在背压暂停期间关闭时，网关暂时移除其轮询注册，待客户端缓冲区降到低水位后继续读取。监听地址固定为 `127.0.0.1`，便于本地开发。

## 协议

每帧是 `4 字节大端长度 | 1 字节类型 | 负载`。长度包含类型字节，不包含自身。`0x01` 是数据，`0x02` 是 Ping，`0x03` 是 Pong。Ping/Pong 无负载，数据负载最大 64 KiB。非法帧关闭该客户端会话。TCP 拆包和粘包由流式解码器处理。

## 构建与运行

需要 C++20 编译器、CMake 3.16+ 和 Python 3。Linux 使用 `epoll`；Windows 使用 `WSAPoll` 运行相同行为测试。

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release
ctest --test-dir build -C Release --output-on-failure
```

开两个终端：

```bash
python scripts/mock_room.py --port 9001
./build/game_edge 9000 127.0.0.1 9001
```

Windows 可运行 `build/Release/game_edge.exe`（多配置生成器）或实际构建产物所在路径。可选 `--idle-ms 30000` 调整客户端空闲时间；默认 30 秒。按 Ctrl+C 停止接收新连接，最多等待 5 秒关闭现有会话。退出时在标准错误输出会话与字节计数。

## 压测

先启动模拟房间服务和网关，再运行：

```bash
python scripts/bench.py --port 9000 --clients 16 --requests 100 --payload-bytes 128
```

脚本输出环境、并发量、总请求数、吞吐和 P50/P99 请求往返延迟。它是本机顺序请求/响应工作负载，不等于生产游戏流量，也不自动与其他网关进行公平比较。请保存原始 JSON、机器规格和构建参数后再在简历中引用数字。

## 当前边界与后续方向

当前没有 TLS、认证、房间路由、UDP 或集群控制。单事件循环中还需用 Linux 压测与 profiler 验证性能瓶颈，才能判断是否增加多 reactor、批量发送或更细的内存管理。后续优先做多上游房间路由与真实负载测试，不预设优化能带来的提升。

## 项目用途

此仓库展示第一阶段实现和设计取舍。面试时可以围绕分帧、非阻塞连接、慢客户端背压、上游故障隔离与可复现压测讨论，不应把模拟房间服务描述成完整游戏服务器。
