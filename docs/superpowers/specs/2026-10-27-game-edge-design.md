# GameEdge 第一阶段设计

## 目标

为通用高性能 C++ 后端岗位制作一个可运行、可测试的游戏长连接网关项目。第一阶段交付 Linux/C++20 TCP 网关核心：客户端通过网关与本地房间服务通信，网关处理连接生命周期、消息分帧、心跳、超时和缓冲区背压。性能声明只来自可复现的测量。

## 使用场景

一个玩家客户端与网关建立 TCP 长连接。客户端发送消息帧，网关与配置的房间服务建立上游连接并转发消息。房间服务的回复沿原连接返回。网关处理 Ping/Pong，不把心跳转发给房间服务。

## 协议

- 每帧由 4 字节网络字节序长度、1 字节类型和负载构成。长度包含类型字节，不包含长度字段。
- 类型：`0x01` 数据，`0x02` Ping，`0x03` Pong。Ping/Pong 负载为空。
- 单帧负载上限 64 KiB。未知类型、零长度、超长帧应关闭客户端连接。
- 数据帧的负载对网关不透明；上游只收数据帧，上游回复也必须是数据帧。
- 拆包与粘包是正常输入，不得丢帧或合帧。

## 网关行为

- 监听指定端口，连接到一个配置的 TCP 上游。上游连接失败时只关闭对应客户端，不影响其他会话。
- Linux 使用非阻塞 socket 与 `epoll`，单事件循环处理客户端和上游；Windows 开发环境可用 `WSAPoll` 跑相同的行为测试。多线程和多 reactor 留到后续阶段。
- 每个方向的待写缓冲区有硬上限 1 MiB。达到高水位 768 KiB 时暂停读取源连接；回落到 256 KiB 后恢复读取。若单次加入会超过硬上限，关闭该会话。
- 客户端空闲 30 秒后关闭。Ping/Pong 算活动；上游数据不延长客户端空闲时间。
- `SIGINT`/`SIGTERM`（Windows 控制台中断）使网关停止接收新连接，并在 5 秒内清理现有会话退出。
- 只记录连接数、字节数与关闭原因等基础指标；本阶段不宣称具体吞吐和延迟。

## 第一阶段交付

- C++20 源码、CMake 配置、一个可执行网关。
- Python 标准库编写的模拟房间服务和端到端测试；C++ 单元测试覆盖帧解析。
- README 包含架构、编译运行、协议和测试方法；基准脚本记录环境、并发、吞吐与延迟分位数。

## 暂不实现

玩家认证、房间分片、UDP、TLS、复杂游戏逻辑、跨机集群和生产级 HTTP 管理接口。这些能力在核心正确性与压测结果稳定后再判断是否加入。

## 验收

1. 部分帧、连续帧和多个并发客户端收到正确回复。
2. Ping 在网关得到 Pong，上游看不到心跳。
3. 非法帧、断开的上游及空闲客户端只影响所属会话。
4. 慢上游/慢客户端不会让网关缓冲区无限增长。
5. Linux CI 编译、单元测试和端到端测试通过；本机开发测试也可运行。
